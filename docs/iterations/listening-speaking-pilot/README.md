## 已确认的决定

- 前两周试点，融入 Today；独立 Words/Patterns 入口保留。
- 预设录音角色练习，不自动理解回答或评估发音。
- 口语默认必做，可以跳过待补；不阻止下一天。
- 录音只保存在当前设备，支持回听和删除。
- 分层提示，记录回答时使用的帮助；反馈后查看答案不污染原尝试。
- 轻量日练与每周综合任务结合。用户授权后续采用推荐方案，在大阶段结束统一 review。

## 本阶段推荐决定

- 三个试点场景为认识一个人、介绍朋友、寻找物品，与现有前两周内容匹配。买东西、约时间移至后续课程。
- 本地录音预算 100 MiB，80 MiB 提醒；单条最多 60 秒/5 MiB，每任务轮次保留最近 3 条。属于产品默认值，实施时需真机验证。
- 听力使用现有浏览器 TTS；不保证离线可用，不新增音频云服务。固定素材录音可在后续替换。
- 全部试点任务启用独立训练版本；旧用户已完成记录不被追溯改为未完成。

## 阶段门槛

阶段一：需求、代表性完整样例、技术方案和可执行验收项，本次已形成草稿。

阶段二：一个真实课程日的端到端功能，包括本地存储、TTS 停止后录音、回放后自评、提示记录和待补状态。已完成 Day 1，已通过单元、仓储、全量回归和构建验证；实际麦克风授权/录制/回放仍需真机确认。现在进入统一演示与 review。

阶段三：填充 14 天完整内容、真机回归、学习试用，再作发布决定。样例文档提供编排和三个对话，不冒充已完成全部生产内容。

## Review 重点

- 每天任务量是否可接受，哪些已有重复输出被替换。
- 用户能否理解“本课可继续、口语待补、自评完成”的区别。
- 首份课程的提示和参考表达是否足够简单。
- 三个场景、录音保留策略及旧用户继续路径是否符合预期。

粗排开发约 6–8 周，仅为范围估算；完成录音兼容性验证及首日纵向实现后重新估算。不在本阶段提交、推送或发布应用。
